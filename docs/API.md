# API Reference

Base path: `/api`. Every route requires `Content-Type: application/json` and `x-internal-api-key: <INTERNAL_API_KEY>`. Requests without a valid key receive `401`; the key is intended for a trusted website/backend, not an end-user browser.

The complete machine-readable contract is [OpenAPI 3.0.3](openapi.json). `GET /docs` serves a local Swagger UI and `GET /openapi.json` serves the same contract when Swagger is enabled. They never call Hago; Swagger is enabled by default outside production and requires `SWAGGER_ENABLED=true` in production. `GET /health` and `GET /ready` are the only unauthenticated routes.

The established authentication and read-only operations below have each been `LIVE-VERIFIED` once with an authorized controlled account, including `nobility-purchase-readiness`. Diamond and Crystal are each also `LIVE-VERIFIED` once under their guarded one-shot paths; Nobility financial mutation is not. No values from verification are retained here.

The browser frontend sends a stable FingerprintJS `visitorId` to the website/backend. The website/backend forwards it as `deviceId` to this adapter using `x-internal-api-key`; that key must never be sent to browser code.

Identifier mapping is explicit: `h_open_id` is UAAS identity metadata, `hagouid` is the authenticated account's internal Hago UID, and a user-visible VID resolves to a target UID through `Uinfo.GetUinfoByVidVer`. These values are not interchangeable. Controlled testing exposed and corrected the prior `h_open_id`-as-UID defect; no real identifiers are documented.

| Method | Endpoint | Body | Current behavior |
| --- | --- | --- | --- |
| GET | `/health` | — | Liveness only; no authentication, database requirement, or Hago call. Returns `200 { status: "OK" }`. |
| GET | `/ready` | — | Local readiness only; no Hago call. Returns `200 READY` only with valid required configuration and a connected MongoDB, otherwise `503 NOT_READY`. |
| POST | `/auth/send-otp` | `phone`, `countryCode` | Validates/rate-limits then sends the confirmed SHA-256-signed UAAS OTP request; LIVE-VERIFIED once. |
| POST | `/auth/verify-otp` | `phone`, `otp`, `deviceId`; optional `country`, `language` | Requires an unexpired local OTP request. `deviceId` must be trusted and stable. Uses the confirmed TripleDES-CBC/PKCS7 `ts` rule, then prefers complete authoritative `Set-Cookie` values or uses the confirmed browser `s_session`/`s_t` fallback. Missing device IDs return `503` before HTTP. LIVE-VERIFIED once; never returns Hago cookies/session values. |
| POST | `/bot/session/validate` | `agentPhone` | Probes authenticated `getMobile` and returns only `VALID`, `REJECTED`, or `UNKNOWN`; LIVE-VERIFIED once and never returns upstream profile/mobile data. |
| POST | `/bot/transfer-readiness` | `agentPhone` | Strictly read-only diagnostic. Separately returns `agencyDiamondCurrency`, `effectiveTransferCurrency`, `walletDiamondLegacyAvailable`, and `walletDiamondNewAvailable`; wallet balances never choose the transfer currency. It never accepts a password or calls transfer/password-mutation endpoints. |
| POST | `/bot/nobility-readiness` | `agentPhone`, `targetId` | Strictly read-only authenticated yMicro diagnostic. It resolves the VID, calls ListAllNobleConf and GetUserNoble, and returns sanitized current/config state. LIVE-VERIFIED once. It never calls `BuyNobleByAgency` or alters financial state. |
| POST | `/bot/nobility-purchase-readiness` | `agentPhone`, `targetId`, numeric `nobilityType` (`1`–`4`) | LIVE-VERIFIED strictly read-only current eligibility check. It validates the stored session, resolves VID to UID, obtains fresh Noble config/state and legacy Diamond wallet data, then derives Purchase/Renew and current cost internally. It returns sanitized eligibility only; no mutation flags, controlled header, or idempotency key are required. It creates no transaction intent, does not authorize a purchase, and never calls `BuyNobleByAgency`. |
| POST | `/bot/verify-id` | `agentPhone`, `targetId` | Performs authenticated yMicro VID lookup with that agent's stored cookies; LIVE-VERIFIED once. |
| POST | `/bot/agent-profile` | `agentPhone` | Performs authenticated yMicro profile lookup using the stored session's internal `hagouid`, never `h_open_id`; LIVE-VERIFIED once. |
| POST | `/bot/wallet-balance` | `agentPhone` | Performs signed read-only wallet query and returns `{ wallet: { balances: { hagoDiamond, hagoDiamondNew, hagoCrystal } } }`; missing balances are `null`. LIVE-VERIFIED once. |
| POST | `/bot/account-history` | `agentPhone`; optional `optTypes`, `page`, `pagesize`, paired `startTime`/`endTime`, `vid`, `currencyTypeList` | Signed read-only history query. Defaults are page `1` and page size `20`; page size is capped at `100`, page at `10000`, and explicit ranges at 31 days. LIVE-VERIFIED once; an empty history is valid for the tested default query. It is not an authoritative settlement ledger. |
| POST | `/bot/transactions` | `agentPhone` | Lists local transaction attempts. |
| POST | `/bot/auto-recharge/diamond/preview` | `agentPhone`, `targetId`, `amount` | Local-only structural parity preview. It normalizes the amount and reports types, field/property order, header names, and cookie names only. It does not load an account, decrypt a session, resolve VID, query wallet, or make any upstream request; `currencyType` is therefore `null` while its required wire type is reported as `number`. |
| POST | `/bot/auto-recharge/crystal/preview` | `agentPhone`, `targetId`, `amount` | Local-only structural preview using fixed confirmed Crystal currency `1826`. Returns only types and multipart/data property names; it does not load a session or call Hago. |
| POST | `/bot/auto-recharge/nobility/preview` | `agentPhone`, `targetId`, `nobilityType`; optional `buyType` (`1` or `2`) | Local-only Noble RPC/payload metadata preview. It returns no IDs, price, package, session, or request values and never calls Hago. |
| POST | `/bot/auto-recharge/diamond` | `agentPhone`, `targetId`, `amount` | Default behavior records `UNKNOWN/NOT_SENT` and returns `503`. LIVE-VERIFIED once in controlled mode with agency-selected `1835`: `code === 1` and wallet reduction equal to the sent amount. Transfer currency is agency `1805`/`1835` or default `1805`; `1835` fails locally with `DIAMOND_MIN_AMOUNT` below `200`. A pre-fix wallet-selected `1805` request returned `-500`; it is historical evidence only and does not alter the live-verified outcome. |
| POST | `/bot/auto-recharge/crystal` | `agentPhone`, `targetId`, `amount` | Same guarded one-shot behavior; Crystal uses fixed confirmed currency `1826`. LIVE-VERIFIED once: one authorized controlled request returned `code === 1` and the wallet balance decreased by exactly the sent amount. Before every guarded send, the adapter requires the bundle-confirmed browser preflight: a positive whole-number amount up to seven digits, a normalized Crystal balance covering the requested amount, and a positive `transferMax` when supplied. |
| POST | `/bot/auto-recharge/nobility` | `agentPhone`, `targetId`, numeric `nobilityType` (`1`–`4`) | **Financial mutation.** Requires `Idempotency-Key` and normal internal API authentication. `HAGO_NOBILITY_ENABLED=true` is required; no controlled-test header or ceiling applies. It rejects caller-supplied price, Diamond amount, pack, buy type, or buyer UID, then refetches session/config/state/wallet and derives every purchase field from current Hago data. A successful execution may deduct that dynamically resolved Diamond cost. `BuyNobleByAgency` is not LIVE-VERIFIED; first live financial outcome pending. |
| POST | `/bot/transactions/reconcile` | `agentPhone`, `transactionId`; optional bounded history filters | Manual read-only helper for an attempted `UNKNOWN` transaction. It queries wallet/history but always leaves local mutation status unchanged. |

The readiness response exposes only normalized fields. Permission `status` values are retained as raw numbers because their broader meaning is not inferred; password presence is `true` only for the bundle-confirmed `has_psw` code `1`. All errors use `{ "status": "ERROR", "message": "…", "code": "…" }` where `code` is available. A missing trusted device ID blocks SMS auth before HTTP. A financial send is persisted as `SEND_PENDING` before its only upstream attempt; timeout/network ambiguity is never retried. Nobility is separately production-enabled only when `HAGO_NOBILITY_ENABLED=true`, remains idempotent, and still has no live financial verification. See [Integration Recovery](INTEGRATION_RECOVERY.md) and [OpenAPI](openapi.json) for protocol confidence and the financial-mutation contract.
